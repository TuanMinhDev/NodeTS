================================================================================
I. TỔNG QUAN HỆ THỐNG
================================================================================

NodeTS là hệ thống Backend cho nền tảng thương mại điện tử đa người bán
(Multi-vendor E-Commerce Marketplace) tương tự mô hình Shopee / Lazada / Tiki.

Hệ thống cho phép:
  - Seller (người bán) mở gian hàng, đăng bán sản phẩm, xử lý đơn hàng.
  - User (người mua) khám phá, mua sắm, đánh giá và tương tác với cửa hàng.
  - Admin (quản trị viên) giám sát và điều hành toàn bộ nền tảng.

Các tính năng cốt lõi:
  - Đăng ký / Đăng nhập / Quản lý tài khoản (JWT, Refresh Token)
  - Quản lý địa chỉ đa loại (nhà riêng, văn phòng, kho hàng)
  - Quản lý danh mục sản phẩm
  - Đăng bán sản phẩm với biến thể (màu sắc, kích thước, giá, tồn kho)
  - Upload ảnh sản phẩm lên CDN Cloudinary
  - Giỏ hàng thông minh (tự động áp giảm giá, kiểm tra biến thể)
  - Đặt hàng với 3 phương thức vận chuyển (tiết kiệm, nhanh, hỏa tốc)
  - Tính phí vận chuyển tự động theo khoảng cách địa lý
  - Quản lý trạng thái đơn hàng
  - Bình luận và đánh giá sản phẩm (chỉ sau khi nhận hàng)
  - Danh sách yêu thích
  - Theo dõi gian hàng (Follow/Unfollow Seller)
  - Nhắn tin trực tiếp (1-1 và nhóm) với hỗ trợ ảnh, trả lời, chỉnh sửa
  - Thông báo real-time qua Socket.IO


================================================================================
II. KIẾN TRÚC VÀ CÔNG NGHỆ
================================================================================

Ngôn ngữ     : TypeScript
Runtime      : Node.js
Framework    : Express.js
Database     : MongoDB (ODM: Mongoose)
Auth         : JSON Web Token (JWT) - Access Token (1h) + Refresh Token (7 ngày)
File Storage : Cloudinary (upload ảnh sản phẩm, ảnh tin nhắn)
Real-time    : Socket.IO (thông báo real-time, chat real-time)
File Upload  : Multer (xử lý multipart/form-data)

Cấu trúc thư mục (theo Domain-Driven Design):
  src/
    _component/     - Shared types, middleware, utils dùng chung
    auth_user/      - Xác thực, đăng ký, quản lý người dùng
    address/        - Quản lý địa chỉ giao hàng/kho hàng
    category/       - Quản lý danh mục sản phẩm
    product/        - Quản lý sản phẩm, biến thể, ảnh
    cart/           - Giỏ hàng
    order/          - Đặt hàng, phí vận chuyển, trạng thái đơn
    comment/        - Bình luận, đánh giá sản phẩm
    favorite/       - Danh sách yêu thích
    follower/       - Theo dõi người bán
    message/        - Tin nhắn, hội thoại
    notification/   - Thông báo hệ thống real-time

Mỗi domain gồm: model/ + controller/ + router (+ middleware/ + service/ nếu cần)

III. PHÂN QUYỀN VÀ XÁC THỰC (AUTH & RBAC)
================================================================================

3.1. Các vai trò (Roles)
-------------------------
  Role "admin"  : Quản trị viên hệ thống. Có toàn quyền trên mọi resource.
  Role "seller" : Người bán / chủ gian hàng.
  Role "user"   : Người mua thông thường. (Mặc định khi đăng ký)

3.2. Cơ chế xác thực
----------------------
  - Khi đăng nhập thành công, hệ thống cấp Access Token (JWT, hết hạn sau 1 giờ).
  - Token được gửi kèm theo mỗi request qua HTTP Header:
      Authorization: Bearer <token>   HOẶC   token: <token>
  - Khi Access Token hết hạn, client dùng Refresh Token (hết hạn sau 7 ngày)
    để lấy cặp token mới (cả Access Token và Refresh Token mới - Token Rotation).
  - Dữ liệu user lưu tách biệt: UserModel (thông tin) và AuthModel (mật khẩu).

3.3. Middleware phân quyền
---------------------------
  - verifyToken   : Xác thực JWT, gắn thông tin user vào request.
  - checkPermission([roles]) : Kiểm tra role. Trả 403 nếu không đủ quyền.
  - checkId()     : So khớp userId trong token với param :id trong URL.

IV. LUỒNG NGHIỆP VỤ ADMIN
================================================================================

Admin là vai trò cao nhất, có quyền truy cập và can thiệp vào mọi tài nguyên
trên toàn hệ thống. Dưới đây là các luồng nghiệp vụ Admin thực hiện:

4.1. Quản lý Người dùng
------------------------
  BƯỚC 1: Admin đăng nhập bằng email/số điện thoại + mật khẩu.
  BƯỚC 2: Hệ thống cấp JWT token, Admin lưu và dùng cho các request tiếp theo.

  Danh sách người dùng:
    - Admin gọi GET /user/all để lấy danh sách tất cả tài khoản trong hệ thống.
    - Hỗ trợ lọc theo tên (search / keyword / q / name) và lọc theo role.
    - VD: GET /user/all?role=seller&search=Nguyen → lấy tất cả seller tên Nguyen

  Xóa người dùng:
    - Admin gọi DELETE /user/delete/:id để xóa vĩnh viễn tài khoản bất kỳ.
    - Chỉ Admin mới có quyền này, Seller và User không thể tự xóa tài khoản.

4.2. Quản lý Danh mục sản phẩm
--------------------------------
  - Admin tạo danh mục mới: POST /category/ (cần: name, description tùy chọn)
  - Hệ thống kiểm tra trùng lặp tên danh mục trước khi tạo.
  - Admin cập nhật tên/mô tả danh mục: PUT /category/:id
  - Admin xóa danh mục: DELETE /category/:id
  - Danh mục công khai, bất kỳ ai cũng xem được (không cần đăng nhập).

4.3. Quản lý Sản phẩm
-----------------------
  - Admin xem toàn bộ sản phẩm của tất cả seller: GET /product/seller
    (không truyền ?sellerId thì lấy hết; truyền thì lọc theo seller cụ thể)
  - Admin có thể cập nhật hoặc xóa bất kỳ sản phẩm nào (kể cả sản phẩm của
    seller khác) vì vai trò admin bỏ qua kiểm tra quyền sở hữu trong controller.
  - Điều này cho phép Admin can thiệp khi phát hiện nội dung vi phạm.

4.4. Quản lý Đơn hàng
-----------------------
  - Admin xem toàn bộ đơn hàng: GET /order/seller (không truyền ?sellerId)
  - Admin xem đơn của một seller cụ thể: GET /order/seller?sellerId=<id>
  - Admin xem chi tiết bất kỳ đơn nào: GET /order/seller/:id
  - Admin cập nhật trạng thái bất kỳ đơn hàng: PUT /order/status/:id
    Trạng thái hợp lệ: "pending" | "shipping" | "delivered" | "cancelled"

4.5. Quản lý Địa chỉ
----------------------
  - Admin có thể thêm, xem, sửa, xóa địa chỉ cho tài khoản của mình.
  - Admin không bị ràng buộc bởi rule "phải có warehouse" như Seller.

4.6. Theo dõi và Thông báo
----------------------------
  - Admin nhận thông báo hệ thống giống như user và seller.
  - Admin có thể xem danh sách người theo dõi của bất kỳ seller nào.


================================================================================
V. LUỒNG NGHIỆP VỤ SELLER (NGƯỜI BÁN)
================================================================================

Seller là người mở gian hàng trên nền tảng. Toàn bộ vòng đời kinh doanh của
Seller được mô tả từ bước thiết lập gian hàng đến khi xử lý xong đơn hàng.

5.1. Thiết lập Gian hàng (Onboarding)
---------------------------------------
  BƯỚC 1 - Đăng ký tài khoản Seller:
    - Gọi POST /user/register với body: { email, password, name, phoneNumber, role: "seller" }
    - Hệ thống kiểm tra email và số điện thoại không được trùng.
    - Tạo 2 bản ghi: UserModel (thông tin) và AuthModel (mật khẩu).
    - Kết quả: Tài khoản với role = "seller" được tạo.

  BƯỚC 2 - Đăng nhập:
    - Gọi POST /user/login với body: { identifier, password }
    - identifier có thể là email hoặc số điện thoại.
    - Nhận về: JWT access_token (1 giờ) và refreshToken (7 ngày).

  BƯỚC 3 - Thiết lập Địa chỉ Kho hàng (BẮT BUỘC):
    - Seller PHẢI thêm ít nhất 1 địa chỉ loại "warehouse" trước khi bán hàng.
    - Gọi POST /address/ với body:
      { fullName, phoneNumber, province, district, ward, street, type: "warehouse" }
    - Nếu chưa có warehouse, hệ thống từ chối thêm địa chỉ loại khác.
    - Địa chỉ warehouse được dùng để tính phí vận chuyển cho khách hàng.
    - Seller chỉ được có đúng 1 địa chỉ warehouse; không thể xóa warehouse
      cuối cùng; không thể đổi warehouse duy nhất sang loại khác.
    - Seller có thể thêm thêm địa chỉ loại "home" hoặc "office" cho cá nhân.
    - Có thể đặt 1 địa chỉ làm mặc định: PUT /address/:id/default

  BƯỚC 4 - Xem thông tin Hồ sơ Gian hàng:
    - Trang public của seller: GET /user/seller/:sellerId (không cần đăng nhập)
    - Trả về: tên gian hàng (shopName), tỉnh/quận/phường của kho hàng.
    - Không lộ số điện thoại hay địa chỉ chi tiết ra ngoài.

5.2. Quản lý Danh mục (tuỳ chọn)
-----------------------------------
  - Seller có thể tạo danh mục cho sản phẩm của mình: POST /category/
  - Cập nhật danh mục: PUT /category/:id
  - Seller chia sẻ danh mục chung với admin (không có scope riêng).

5.3. Đăng bán Sản phẩm
------------------------
  BƯỚC 1 - Upload sản phẩm: POST /product/create (multipart/form-data)
    Fields bắt buộc:
      name        : Tên sản phẩm
      description : Mô tả chi tiết
      category    : ID danh mục
      variants    : JSON string array, mỗi phần tử gồm:
                    { color, size, stock, sold, price }
                    - color : màu sắc (VD: "Đỏ", "Xanh navy",...)
                    - size  : kích thước (VD: "S", "M", "L", "XL",...)
                    - stock : số lượng tồn kho (>= 0)
                    - sold  : số lượng đã bán (>= 0, khởi đầu = 0)
                    - price : giá bán (> 0, đơn vị VND)
    Fields tùy chọn:
      sale        : Phần trăm giảm giá (VD: 10 tức là giảm 10%)
      images      : File ảnh (tối đa 10 ảnh, upload qua Multer → Cloudinary CDN)

    Quy tắc validation variants:
      - Mảng variants không được rỗng.
      - Mỗi variant phải có đủ: color, size, stock, sold, price.
      - stock >= 0, sold >= 0, price > 0.

  BƯỚC 2 - Hệ thống xử lý ảnh:
    - Multer nhận file ảnh vào bộ nhớ đệm (buffer).
    - Cloudinary upload_stream xử lý song song toàn bộ ảnh (Promise.all).
    - Trả về danh sách URL CDN, lưu vào product.images.

  BƯỚC 3 - Lưu sản phẩm:
    - Bản ghi Product được tạo với sellerId = userId của token.
    - isActive = true (mặc định).
    - timestamps: createdAt, updatedAt tự động ghi nhận.

  BƯỚC 4 - Kích hoạt thông báo tự động:
    - Sau khi lưu thành công, hệ thống gọi notifyProductCreated().
    - Hàm này tìm tất cả người đang follow seller này.
    - Gửi thông báo "Sản phẩm mới" tới từng follower.
    - Gửi thêm thông báo xác nhận "Tạo sản phẩm thành công" về cho chính seller.

5.4. Cập nhật Sản phẩm
------------------------
  - Gọi PUT /product/:id (multipart/form-data)
  - Seller chỉ cập nhật được sản phẩm của mình (kiểm tra sellerId).
  - Hỗ trợ thêm ảnh mới (ghép vào mảng images hiện có).
  - Hỗ trợ xóa ảnh cụ thể: truyền thêm removeImages = ["url1", "url2"].
  - Cập nhật phần trăm sale: truyền sale=null để bỏ giảm giá.

5.5. Xóa Sản phẩm
-------------------
  - Gọi DELETE /product/:id
  - Seller chỉ xóa được sản phẩm của mình.

5.6. Xem Danh sách Sản phẩm của Shop
--------------------------------------
  - GET /product/seller → trả về tất cả sản phẩm của seller đang đăng nhập.
  - Hỗ trợ phân trang: ?pageNumber=1&pageSize=10

5.7. Xử lý Đơn hàng
---------------------
  BƯỚC 1 - Seller xem đơn hàng mới:
    - GET /order/seller → danh sách đơn hàng gửi đến gian hàng mình.
    - Mỗi đơn có đầy đủ: thông tin người mua, danh sách sản phẩm, địa chỉ giao.
    - Sắp xếp theo thời gian tạo mới nhất trước.

  BƯỚC 2 - Xem chi tiết một đơn:
    - GET /order/seller/:id → chi tiết đơn bao gồm:
      + Thông tin người mua: tên, email, số điện thoại.
      + Danh sách sản phẩm: biến thể, số lượng, giá.
      + Địa chỉ giao hàng, phương thức vận chuyển, phí ship.
      + Trạng thái hiện tại và thời gian tạo đơn.

  BƯỚC 3 - Cập nhật trạng thái đơn hàng:
    - PUT /order/status/:id với body: { status }
    - Các trạng thái và ý nghĩa:
        "pending"   → Đơn mới, chờ xác nhận từ seller.
        "shipping"  → Seller đã xác nhận, đang giao hàng tới khách.
        "delivered" → Giao hàng thành công.
        "cancelled" → Đơn bị hủy.
    - Sau khi cập nhật, hệ thống tự động gửi thông báo tới người mua.
    - VD: Nếu status = "shipping" → buyer nhận: "Đơn hàng ORD... đang được giao"
    - VD: Nếu status = "delivered" → buyer nhận: "Đơn hàng ORD... giao thành công"

5.8. Nhắn tin với Khách hàng (Seller side)
--------------------------------------------
  - Seller sử dụng module Message để giao tiếp với người mua.
  - Seller có thể xem tất cả hội thoại của mình: GET /message/conversations
  - Seller gửi tin nhắn (text hoặc ảnh): POST /message/send
  - Seller đánh dấu đã đọc: PUT /message/read/:conversationId
  - Khi seller gõ phím, hệ thống phát sự kiện "typing" real-time tới khách.

5.9. Quản lý Người theo dõi (Followers)
-----------------------------------------
  - Seller xem danh sách người đang follow mình: GET /follower/followers/:sellerId
  - Chỉ chính seller đó hoặc admin mới xem được danh sách followers.
  - Seller nhận thông báo gián tiếp (qua notification) khi có follower mới
    đặt hàng hoặc có sự kiện liên quan.

5.10. Thông báo Seller
-----------------------
  Seller nhận các loại thông báo sau:
  - "Tạo sản phẩm thành công": mỗi khi đăng sản phẩm mới.
  - "Bạn có đơn hàng mới"    : mỗi khi có người mua đặt hàng từ shop mình.
  - Thông báo hệ thống khác theo nghiệp vụ mở rộng sau này.


================================================================================
VI. LUỒNG NGHIỆP VỤ USER (NGƯỜI MUA)
================================================================================

User là vai trò người mua hàng. Toàn bộ hành trình mua sắm từ tìm kiếm sản
phẩm cho đến đánh giá sau khi nhận hàng được mô tả chi tiết dưới đây.

6.1. Đăng ký và Đăng nhập
---------------------------
  BƯỚC 1 - Đăng ký: POST /user/register
    body: { email, password, name, phoneNumber }
    (Không truyền role → hệ thống tự gán role = "user")
    Kiểm tra: Email và số điện thoại phải là duy nhất trong hệ thống.

  BƯỚC 2 - Đăng nhập: POST /user/login
    body: { identifier, password }
    identifier: email hoặc số điện thoại.
    Nhận về: { token (access_token), refreshToken }

  BƯỚC 3 - Duy trì phiên: POST /user/refresh-token
    Khi access_token hết hạn (1 giờ), gửi refreshToken để lấy cặp token mới.
    Cơ chế Refresh Token Rotation: cả access_token và refresh_token đều được
    cấp mới, refresh_token cũ không dùng được nữa (an toàn hơn).

  BƯỚC 4 - Đổi mật khẩu: POST /user/change-password
    body: { oldPassword, newPassword }
    Ràng buộc: newPassword phải khác oldPassword.

  BƯỚC 5 - Cập nhật thông tin: PUT /user/update-info
    body: { name, email, phoneNumber, address }
    Hệ thống kiểm tra email/số điện thoại mới không được trùng với tài khoản khác.

6.2. Quản lý Địa chỉ Giao hàng
---------------------------------
  User quản lý sổ địa chỉ cá nhân, dùng khi đặt hàng và tính phí ship.

  - Thêm địa chỉ: POST /address/
    body: { fullName, phoneNumber, province, district, ward, street, type, isDefault }
    type hợp lệ cho user: "home" hoặc "office" (không cần warehouse).
    Nếu isDefault = true → hệ thống tự bỏ isDefault của các địa chỉ cũ.

  - Xem danh sách địa chỉ: GET /address/ (hỗ trợ phân trang)
  - Xem chi tiết 1 địa chỉ: GET /address/:id
  - Cập nhật địa chỉ: PUT /address/:id
  - Xóa địa chỉ: DELETE /address/:id
  - Đặt địa chỉ mặc định: PUT /address/:id/default

6.3. Khám phá và Tìm kiếm Sản phẩm
-------------------------------------
  User tìm kiếm hàng hóa qua: GET /product/get

  Bộ lọc tìm kiếm đa tầng:
    ?name=<text>        → Tìm theo tên sản phẩm (regex, không phân biệt hoa thường)
    ?category=<text>    → Lọc theo tên danh mục
    ?minPrice=<số>      → Giá tối thiểu (lọc trên variants.price)
    ?maxPrice=<số>      → Giá tối đa
    ?onSale=true        → Chỉ lấy sản phẩm đang giảm giá
    ?color=<text>       → Lọc theo màu sắc biến thể
    ?size=<text>        → Lọc theo kích thước biến thể
    ?sellerId=<id>      → Lọc sản phẩm của một seller cụ thể
    ?pageNumber=<n>     → Trang hiện tại (mặc định = 1)
    ?pageSize=<n>       → Số sản phẩm mỗi trang (mặc định = 10)

  Kết quả trả về: { items, totalItems, totalPages, currentPage }
  Sắp xếp: Sản phẩm mới nhất hiển thị trước (sort: createdAt descending).
  Mỗi sản phẩm trả về thông tin sellerId đã được populate (tên, email, avatar).

  Xem chi tiết sản phẩm: GET /product/:id
    Trả về toàn bộ thông tin: tên, mô tả, danh sách variants, ảnh, seller.

  Xem thông tin gian hàng người bán: GET /user/seller/:sellerId
    Trả về: tên gian hàng, tỉnh/quận/phường kho hàng (không lộ SĐT).

6.4. Thêm vào Giỏ hàng
------------------------
  User thêm sản phẩm vào giỏ: POST /cart/add

  body: {
    items: [
      {
        productId: "...",
        variant: { color: "Đỏ", size: "M" },
        quantity: 2
      }
    ]
  }

  Logic xử lý:
    1. Hệ thống tìm sản phẩm theo productId trong database.
    2. Kiểm tra variant (color + size) có tồn tại trong sản phẩm không.
    3. Tính giá cuối: nếu sản phẩm đang sale → finalPrice = price × (1 - sale/100).
    4. Kiểm tra trong giỏ hiện tại có item này chưa:
       - Đã có: cộng thêm quantity.
       - Chưa có: thêm item mới vào giỏ.
    5. Tính lại totalPrice của toàn bộ giỏ hàng.
    6. Lưu Cart (status = "active").

  Giỏ hàng: Mỗi user có một Cart document với status "active".
  Lần đầu thêm: tạo mới Cart. Lần sau: cập nhật Cart đang active.

  Xem giỏ hàng: GET /cart/get (hỗ trợ phân trang items)
  Cập nhật số lượng: PUT /cart/update/:itemId body: { quantity }
  Xóa item khỏi giỏ: DELETE /cart/delete body: { itemIds: ["id1", "id2"] }

6.5. Tính Phí Vận chuyển (Trước khi Đặt Hàng)
------------------------------------------------
  User gọi: GET /order/shipping-options
  Params:
    ?addressId=<id>       → ID địa chỉ giao hàng của buyer
    ?productIds=<id1,id2> → Danh sách productId cần mua (phân tách bằng dấu phẩy)

  Logic tính phí:
    1. Tìm địa chỉ buyer theo addressId.
    2. Tìm địa chỉ kho (warehouse) của từng seller trong danh sách sản phẩm.
    3. So sánh tỉnh/thành phố của buyer và seller:
       - Cùng tỉnh/thành → có đủ 3 phương thức: tiết kiệm, nhanh, hỏa tốc.
       - Khác tỉnh/thành → chỉ có 2 phương thức: tiết kiệm, nhanh.

  Cấu trúc phí vận chuyển:
    + economy (Tiết kiệm): cố định 20.000đ/shop
      Thời gian: 3-5 ngày (cùng tỉnh), 5-7 ngày (khác tỉnh)
    + fast    (Nhanh)    : cố định 35.000đ/shop
      Thời gian: 1-2 ngày (cùng tỉnh), 2-3 ngày (khác tỉnh)
    + express (Hỏa tốc) : theo km = khoảng cách × 4.000đ/km
      - Chỉ áp dụng khi: cùng tỉnh/thành VÀ chỉ 1 seller duy nhất.
      - Ước tính khoảng cách:
          Cùng phường/xã    → 2 km
          Cùng quận/huyện   → 8 km
          Cùng tỉnh, khác quận → 20 km
      - Thời gian: "Trong ngày"

    Multi-seller order: Khi đặt hàng nhiều seller cùng lúc,
      phí ship = tổng phí của từng seller, hỏa tốc bị vô hiệu hóa.

6.6. Đặt Hàng
---------------
  User gọi: POST /order/create

  body: {
    sellerId      : ID người bán
    items         : [{ productId, variant: {color, size}, quantity, price }]
    shippingAddress: {
      fullName, phoneNumber, address, city, district, ward
    }
    shippingMethod: "economy" | "fast" | "express"
    notes         : ghi chú tùy chọn
  }

  Logic phía server:
    1. Validate tất cả items (productId, variant, quantity, price).
    2. Tính shippingFee phía server (không tin client):
       - economy → 20.000đ
       - fast    → 35.000đ
       - express → tính lại theo km từ kho seller đến địa chỉ buyer.
       - express chỉ chấp nhận khi buyer và seller cùng tỉnh.
    3. Tính totalPrice = tổng tiền hàng + shippingFee.
    4. Tạo mã đơn hàng duy nhất: "ORD" + timestamp + chuỗi random.
    5. Lưu Order với status = "pending".
    6. Gửi thông báo tự động:
       - Buyer nhận: "Đặt đơn hàng thành công. Mã đơn: ORDxxxxxx"
       - Seller nhận: "Bạn có đơn hàng mới. Mã đơn: ORDxxxxxx"

  Xem đơn hàng của mình: GET /order/ → danh sách tất cả đơn
  Xem chi tiết đơn: GET /order/:id → chi tiết đơn (chỉ xem được đơn của mình)

6.7. Đánh giá Sản phẩm (Sau khi nhận hàng)
---------------------------------------------
  Chỉ được đánh giá KHI đơn hàng có status = "delivered".

  BƯỚC 1 - Kiểm tra sản phẩm có thể đánh giá:
    GET /comment/order/:orderId/reviewable-items
    → Trả về danh sách items trong đơn chưa được đánh giá.

  BƯỚC 2 - Gửi đánh giá: POST /comment/
  body: {
    productId  : ID sản phẩm
    orderId    : ID đơn hàng
    orderItemId: ID dòng sản phẩm trong đơn (tránh trùng lặp)
    content    : Nội dung bình luận (bắt buộc)
    rating     : Điểm đánh giá từ 1 đến 5 (bắt buộc)
    img        : URL ảnh đính kèm (tùy chọn)
  }

  Quy tắc chống gian lận:
    - Kiểm tra orderId thuộc về user đang đăng nhập.
    - Kiểm tra productId có trong danh sách sản phẩm của đơn đó.
    - Mỗi dòng sản phẩm (orderItemId) chỉ được đánh giá 1 lần duy nhất.
    - Index unique trên (userId, orderItemId) ngăn duplicate.

  Xem đánh giá sản phẩm: GET /comment/product/:productId (không cần đăng nhập)
  Trả về danh sách comment sắp xếp mới nhất trước, kèm tên/email người đánh giá.

6.8. Danh sách Yêu thích
--------------------------
  - Thêm vào yêu thích: POST /favorite/ body: { productId }
    Kiểm tra sản phẩm tồn tại, kiểm tra chưa có trong list mới thêm.
  - Xem danh sách yêu thích: GET /favorite/ (trả về đầy đủ thông tin sản phẩm)
  - Xóa khỏi yêu thích: DELETE /favorite/:productId

6.9. Theo dõi Gian hàng (Follow Seller)
-----------------------------------------
  - Follow: POST /follower/follow body: { sellerId }
    Không thể follow chính mình. Seller phải tồn tại trong hệ thống.
    Kiểm tra chưa follow rồi mới cho phép.
  - Unfollow: DELETE /follower/unfollow/:sellerId
  - Xem danh sách đang follow: GET /follower/following
  - Kiểm tra trạng thái follow: GET /follower/status/:sellerId → { isFollowing: true/false }

6.10. Nhắn tin với Người bán
------------------------------
  BƯỚC 1 - Tạo hoặc mở lại hội thoại: POST /message/conversation
    body: { participantId: <sellerId> }
    Nếu đã có hội thoại 1-1 giữa 2 người → trả về hội thoại cũ.
    Nếu chưa có → tạo hội thoại mới.

  BƯỚC 2 - Gửi tin nhắn: POST /message/send
    body: { conversationId, content }
    Hoặc đính kèm ảnh (upload qua multipart/form-data).
    Hỗ trợ trả lời tin nhắn cụ thể: truyền replyTo = <messageId>.
    Hỗ trợ 2 loại tin: "text" (mặc định) và "image".
    Sau khi gửi: cập nhật lastMessage và lastMessageAt của hội thoại.
    Gửi tin nhắn real-time qua Socket.IO đến tất cả thành viên của hội thoại.

  BƯỚC 3 - Đọc tin nhắn: GET /message/messages/:conversationId
    Phân trang: ?page=1&limit=50
    Không hiển thị tin nhắn đã bị user xóa phía mình.

  BƯỚC 4 - Đánh dấu đã đọc: PUT /message/read/:conversationId
  BƯỚC 5 - Xóa tin nhắn (phía mình): DELETE /message/message/:id
    Tin nhắn không xóa khỏi DB, chỉ ẩn phía người xóa.
  BƯỚC 6 - Chỉnh sửa tin nhắn: PUT /message/message/:id
    Chỉ người gửi mới được sửa.
    Lưu lịch sử chỉnh sửa (editHistory) để audit.

6.11. Thông báo
----------------
  User nhận thông báo: GET /notification/
  Filter: ?isRead=true/false → lọc theo trạng thái đọc.
  Phân trang: ?page=1&limit=10. Response kèm unreadCount.

  Các loại thông báo User nhận:
    - "Đặt đơn hàng thành công": sau khi tạo đơn.
    - "Đơn hàng đang giao"     : khi seller cập nhật → "shipping".
    - "Đơn hàng giao thành công": khi seller cập nhật → "delivered".
    - "Đơn hàng bị hủy"        : khi seller/admin cập nhật → "cancelled".
    - "Sản phẩm mới"           : từ seller mà user đang theo dõi.

  Đánh dấu đọc 1 thông báo: PUT /notification/:id/read
  Đánh dấu đọc tất cả     : PUT /notification/read-all
  Xóa thông báo           : DELETE /notification/:id


================================================================================
VII. LUỒNG TƯƠNG TÁC GIỮA CÁC VAI TRÒ
================================================================================

7.1. Luồng Mua hàng hoàn chỉnh (End-to-End)
---------------------------------------------
  USER                          HỆ THỐNG                     SELLER
  ----                          --------                     ------
  1. Tìm kiếm sản phẩm  ──→  Lọc & trả kết quả  ←──── (Seller đã đăng)
  2. Xem chi tiết sp    ──→  Lấy product + seller info
  3. Thêm vào giỏ       ──→  Kiểm tra variant + tính giá
  4. Tính phí ship      ──→  Tính theo khoảng cách địa lý
  5. Đặt hàng           ──→  Tạo Order (status: pending)
                              Gửi thông báo buyer ─────────→ Gửi thông báo seller
  6. (Chờ xử lý)                                    ←─── Seller xác nhận đơn
                              Cập nhật: "shipping"
                              Thông báo buyer ←──────────── (Seller xử lý)
  7. (Chờ nhận hàng)
                              Cập nhật: "delivered"
                              Thông báo buyer ←──────────── (Giao hàng xong)
  8. Đánh giá sản phẩm  ──→  Lưu comment + rating

7.2. Luồng Thông báo Fan (Follower Notification)
--------------------------------------------------
  USER follow SELLER          ──→  Lưu vào FollowerModel
  SELLER đăng sản phẩm mới   ──→  Hệ thống tìm tất cả followers của seller
                              ──→  Gửi thông báo "Sản phẩm mới" tới TỪNG follower
                              ──→  Gửi socket real-time nếu follower đang online

7.3. Luồng Chat (Message Flow)
--------------------------------
  USER tạo conversation với SELLER  ──→  Kiểm tra đã có hội thoại chưa
  USER gửi tin nhắn                 ──→  Lưu Message
                                    ──→  Cập nhật lastMessage của Conversation
                                    ──→  Socket emit "newMessage" tới SELLER
  SELLER thấy tin nhắn mới (real-time)
  SELLER trả lời                    ──→  Socket emit "newMessage" tới USER
  USER đánh dấu đọc                 ──→  Cập nhật isRead


================================================================================
VIII. CHI TIẾT CÁC MODULE
================================================================================

8.1. Module Xác thực (auth_user)
----------------------------------
  Models:
    UserModel  : { name, email, role, phoneNumber, timestamps }
    AuthModel  : { user_name (email), password, userId (ref User) }
    * Thiết kế tách biệt để dễ mở rộng OAuth/SSO sau này.

  Controllers:
    register        : Tạo UserModel + AuthModel, kiểm tra trùng email/phone.
    login           : Xác thực credentials, cấp JWT access_token + refreshToken.
    logout          : Xóa cookie access_token.
    changePassword  : Kiểm tra oldPassword khớp, cập nhật password mới.
    refreshToken    : Xác thực refreshToken, cấp cặp token mới (Rotation).
    getMe           : Lấy thông tin user hiện tại từ token.
    updateInfoUser  : Cập nhật thông tin, kiểm tra trùng email/phone.
    getAllUser       : Admin-only, filter theo name/role.
    deleteUser      : Admin-only, xóa tài khoản.
    getPublicSellerProfile: Public, trả về tên shop + vị trí kho của seller.

8.2. Module Địa chỉ (address)
-------------------------------
  Model AddressModel: { userId (unique), addresses: [AddressItem] }
  AddressItem: { fullName, phoneNumber, province, district, ward, street,
                 isDefault, type: "home"|"office"|"warehouse" }

  Quy tắc đặc biệt cho Seller:
    - Seller phải thêm address type="warehouse" TRƯỚC KHI thêm loại khác.
    - Seller chỉ có tối đa 1 warehouse.
    - Seller không thể xóa warehouse cuối cùng.
    - Seller không thể đổi warehouse sang loại khác nếu đó là warehouse duy nhất.
    * Warehouse dùng để: hiển thị vị trí gian hàng + tính phí vận chuyển.

8.3. Module Danh mục (category)
---------------------------------
  Model: { name (unique), description, timestamps }
  CRUD đầy đủ. Đọc không cần auth, ghi cần admin/seller.
  Tên danh mục không được trùng (checked before insert).

8.4. Module Sản phẩm (product)
--------------------------------
  Model ProductModel:
    { name, description, categoryId (ref Category), sellerId (ref User),
      sale (% giảm giá, default null), variants: [{color, size, stock, sold, price}],
      images: [String URL], isActive: Boolean, timestamps }

  Middleware uploadProductImages: Multer → bộ nhớ đệm, giới hạn 10 ảnh.
  Hàm uploadToCloudinary: Stream upload, trả về secure_url.

  Bộ lọc tìm kiếm (getProduct):
    - name: regex, case-insensitive.
    - category: regex, case-insensitive.
    - variants.price: $gte / $lte.
    - variants.color / variants.size: regex match.
    - sale !== null: chỉ hàng đang sale.

8.5. Module Giỏ hàng (cart)
-----------------------------
  Model CartModel:
    { userId (ref User), items: [{productId, variant:{color,size}, quantity, price}],
      totalPrice, status: "active"|"inactive", timestamps }

  Logic addToCart:
    - Nếu chưa có cart active → tạo cart mới.
    - Nếu đã có cart → tìm item trùng (productId + color + size):
        Có trùng → cộng quantity.
        Không trùng → push item mới.
    - Áp dụng giá sale tại thời điểm thêm vào giỏ.
    - Tính lại totalPrice sau mỗi thay đổi.

8.6. Module Đơn hàng (order)
------------------------------
  Model OrderModel:
    { userId, sellerId, orderCode (unique), items:[{productId, variant, quantity, price}],
      shippingMethod: "economy"|"fast"|"express", shippingFee, totalPrice,
      shippingAddress: {fullName, phoneNumber, address, city, district, ward},
      status: "pending"|"shipping"|"delivered"|"cancelled", notes, timestamps }

  Phí vận chuyển tính phía server (không tin client):
    RATE_PER_KM  = 4.000đ  (hỏa tốc: phí/km)
    FEE_ECONOMY  = 20.000đ (tiết kiệm: cố định)
    FEE_FAST     = 35.000đ (nhanh: cố định)
    Hỏa tốc: distanceKm × 4.000, chỉ áp dụng cùng tỉnh, 1 seller.

  Hàm estimateDistanceKm:
    Cùng phường/xã    → 2 km
    Cùng quận/huyện   → 8 km
    Cùng tỉnh khác quận → 20 km

8.7. Module Bình luận (comment)
---------------------------------
  Model ProductCommentsSchema:
    { productId (unique String), comment: [CommentItem] }
  CommentItem:
    { userId, orderId, orderItemId (optional), productId, rating 1-5,
      content, img, timestamps }
  Unique indexes:
    (userId, orderItemId) - sparse: ngăn đánh giá trùng theo dòng đơn.
    (userId, orderId, productId) - sparse: fallback cho comment cũ.

  getReviewableItems: Lọc các dòng trong đơn chưa được đánh giá.
  getCommentsByProduct: Công khai, sắp xếp mới nhất trước.

8.8. Module Yêu thích (favorite)
----------------------------------
  Model: { userId (unique), products: [ObjectId ref Product] }
  addToFavorites: Kiểm tra product tồn tại, dùng $addToSet → không duplicate.
  getFavorites: Populate đầy đủ thông tin sản phẩm.

8.9. Module Theo dõi (follower)
---------------------------------
  Model: { sellerId (unique), followers: [{userId, createdAt}] }
  followSeller: Kiểm tra target là seller, không follow chính mình, chưa follow.
  getSellerFollowers: Chỉ chính seller hoặc admin mới xem được.
  checkFollowStatus: Kiểm tra user có đang follow seller không → { isFollowing }.

8.10. Module Tin nhắn (message)
---------------------------------
  Models:
    ConversationModel:
      { participants: [userId], lastMessage, lastMessageAt,
        isGroup, groupName, groupImage, createdBy, isActive }
    MessageModel:
      { conversationId, senderId, content, messageType: "text"|"image",
        imageUrl, isRead: [{userId, readAt}], isDeleted: [{userId, deletedAt}],
        replyTo (ref Message), editedAt, editHistory: [{content, editedAt}] }

  Tính năng nổi bật:
    - Tạo hội thoại 1-1: kiểm tra đã tồn tại, trả về cũ nếu có.
    - Hỗ trợ nhóm chat (isGroup = true, groupName bắt buộc).
    - Gửi ảnh: upload qua Multer → Cloudinary → lưu imageUrl.
    - Trả lời tin nhắn: replyTo tham chiếu đến Message khác.
    - Xóa mềm (soft delete): isDeleted lưu userId đã xóa, không mất data.
    - Sửa tin nhắn: lưu editHistory để audit trail.
    - Read receipt: isRead array lưu ai đã đọc lúc mấy giờ.
    - Real-time: typing indicator (socket events: "typing", "stopTyping").

8.11. Module Thông báo (notification)
---------------------------------------
  Model UserNotificationInboxModel (Inbox Pattern):
    { userId (unique), items: [NotificationItem] }
  NotificationItem:
    { title, message, type: "order"|"payment"|"promotion"|"system"|"comment"|
      "favorite"|"general", relatedId, relatedModel, isRead, priority: "low"|
      "medium"|"high"|"urgent", actionUrl, actionText, imageUrl, metadata,
      expiresAt, sentAt, readAt }

  notifyProductCreated(sellerId, productId, productName):
    → Tìm tất cả followers của seller.
    → Gửi thông báo "Sản phẩm mới" đến từng follower.
    → Gửi thông báo xác nhận về seller.

  notifyOrderCreated(sellerId, buyerId, orderId, orderCode):
    → Seller nhận: "Bạn có đơn hàng mới - Mã: <code>"
    → Buyer nhận: "Đặt đơn hàng thành công - Mã: <code>"

  notifyOrderStatusUpdated(buyerId, orderId, orderCode, status):
    → "shipping"   → "Đơn hàng đang giao đến bạn"
    → "delivered"  → "Đơn hàng đã được giao thành công"
    → "cancelled"  → "Đơn hàng đã bị hủy"

  Socket.IO: Khi user online (joinUserRoom), thông báo push real-time ngay lập tức.
  Nếu user offline: thông báo lưu trong DB, đọc khi online.


================================================================================
IX. QUY TẮC NGHIỆP VỤ QUAN TRỌNG
================================================================================

  1. ĐÁNH GIÁ:
     - Chỉ đánh giá sản phẩm đã mua và đơn hàng đã "delivered".
     - Mỗi dòng sản phẩm trong đơn chỉ đánh giá được 1 lần.
     - Rating phải từ 1 đến 5 sao.

  2. KHO HÀNG SELLER:
     - Seller BẮT BUỘC phải có ít nhất 1 địa chỉ warehouse.
     - Warehouse là dữ liệu quan trọng để tính phí ship cho khách.
     - Nếu seller chưa cấu hình warehouse, hệ thống từ chối tạo shipping options.

  3. GIÁ VẬN CHUYỂN:
     - Server tự tính phí ship; client không được tự khai báo shippingFee.
     - Express chỉ áp dụng khi buyer và seller cùng tỉnh/thành phố.
     - Multi-seller order → hỏa tốc bị vô hiệu; phí = tổng phí từng seller.

  4. PHÂN QUYỀN SẢN PHẨM:
     - Seller chỉ sửa/xóa được sản phẩm mình tạo ra.
     - Admin có thể sửa/xóa bất kỳ sản phẩm nào.

  5. PHÂN QUYỀN ĐƠN HÀNG:
     - User chỉ xem được đơn do mình đặt.
     - Seller chỉ xem/cập nhật trạng thái đơn gửi đến shop mình.
     - Admin xem và cập nhật bất kỳ đơn nào.

  6. FOLLOW:
     - Không thể follow chính mình.
     - Chỉ follow được tài khoản có role "seller".
     - Một user không thể follow cùng một seller nhiều lần.

  7. GIỎ HÀNG:
     - Giá trong giỏ hàng được tính tại thời điểm thêm vào giỏ (snapshot price).
     - Nếu sản phẩm hết hạn sale sau đó, giá trong giỏ không thay đổi.
     - Mỗi user chỉ có 1 cart active tại một thời điểm.

  8. XÓA TIN NHẮN:
     - Xóa mềm phía người dùng, không xóa thật khỏi database.
     - Người nhận vẫn thấy tin nhắn dù người gửi đã xóa phía mình.

  9. MÃ ĐƠN HÀNG:
     - Tự động tạo: "ORD" + Date.now() + chuỗi random 9 ký tự. Là duy nhất.

  10. UPLOAD ẢNH:
     - Sản phẩm: tối đa 10 ảnh, lưu trên Cloudinary folder "products".
     - Tin nhắn: hỗ trợ gửi ảnh qua Multer → Cloudinary.
